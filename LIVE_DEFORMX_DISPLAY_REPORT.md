# DeformX display adapter

Base: 07b848d4b8b0dc77c945b17a15f03c86165f9e57. This opt-in adapter consumes the already captured `material_director` from `NativeParameterEndpoints` under `profile_reader_scope`. It copies actual segment positions and XYZW quaternions and maps local Y/Z/X to the existing wire mesh row convention. It does not alter physics or source cameras. The actual `BackendProfile` is verified, the entire packet source basis must equal the current verified source basis, and source identity, completed clock, rod nodes, and native parameter radius must agree after float32 normalization, matching the native contactRadius representation. Failed publication hides the mesh; caller must call `hide()` when no valid frame exists. Clock checks do not replace exclusive physical-owner read ownership.

Integration: create `display = LiveDeformxDisplay.for_mesh(mesh, radius, source_instance_id=id(owner.rod.rope), backend_profile=owner.backend_profile)` for the visual mesh. Under the owner's exclusive physical read phase, after durable recording, call `snapshot = capture_snapshot(exchange, source_instance_id=id(owner.rod.rope), read_clock=owner.rod.clock, backend_profile=owner.backend_profile)`. The snapshot owns its CPU arrays and retains no exchange or native reference. At publication call `display.publish_snapshot(snapshot, read_clock=owner.rod.clock)`; it refuses different owner/profile/radius or a changed physical clock and leaves the mesh hidden. `display.publish(exchange, source_instance_id=id(owner.rod.rope), read_clock=owner.rod.clock)` combines the two operations. Owner must hide/dispose when the frame is missing, on reset, or on teardown. It does not synchronize future source rod and 640x480 stereo RGB views.
