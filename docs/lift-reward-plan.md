# 抓稳后提升与保持奖励

用户已确认增加上一轮提出的高度进展与低滑移保持奖励。复用真实测量和原有准入，
不修改控制、接触参数、保护、成功判定。原有 lift 奖励已有5分高度差，但未强制当前抓稳。

## 设计

- 增加可选 --stable-lift-reward，仅tensor + measured_load + vertical_force_reward。
- 新模块 StableLiftReward：每回合存 best_height_m、hold_credit_s，两维归一化观测。
- 当前物理子步原本处于lift、有效且无失败、双手满足原载荷窗口、物体速度<0.03m/s、
  相对滑移<=0.002m、手对物体垂向合力(含摩擦)>=0 时才给新奖励。
- 替换原lift项：5 * 新最高离桌高度增量 / 0.03，最高计30mm，总额<=5分。
  高度来自物体bottom-.30，非手掌目标；丢接触/失败不能推进奖励状态。
- 新stable_lift_hold项：bottom>=.303才计，4分/秒 * clip(height/.03,0,1)，
  加权累计时间封顶.5秒，总额<=2分。分段保持也不会重置已发额度。
- 保留3/10mm里程碑与最终30mm连续.5秒成功判定；不提高夹紧力奖励。
- reset只清指定环境；rollout边界不清奖励状态；状态随观测显式暴露。
- 合同记录门槛、额度、测量来源和新增维度。旧合同拒绝静默续训，保留旧检查点。

## 实施顺序

1. 写纯tensor测试：实物升高vs仅手移动、双手门控、滑移/速度/下压力/失败阻断、
   抬落重复、封顶、不同dt等时长、选择复位和观测。运行确认缺少功能失败。
2. 实现独立模块；在Task reset/observe/consume接入，奖励项明确计入日志。
3. 加CLI校验、训练初始化、合同及policy launcher开关；集成回归验证奖励求和、
   原lift项替换、188维观测及旧检查点拒绝。
4. CPU相关回归后中断并保存旧训练，备份修改前文件；同步远端。
5. 确认无并行Isaac后跑2环境48样本真实PPO短测，检查模型/优化器有限、合同和奖励项。
6. 短测完成后开启新256环境训练并更新活动指针。实际成功不能由离线测试推断。
