DH116 V2 官方网站检索与仿真参数对照（2026-10-24）

结论
当前配置不能称为已按 V2 最大力标定。每手反馈目标 0.1–1 N、主动关节 0.2 N·m 上限、10–20 N·m/rad 刚度均是当前仿真选择，不是厂家给出的逐关节实测参数。也不能把手册 14–16 N 直接填入关节力矩上限。

确认的厂家事实
1. V2 手册给出指尖力 14–16 N，整手重量 490±10 g，11 自由度/6 主动自由度，蜗轮蜗杆传动。侧向握力的介绍文字与表格不一致（超50 N / ≤50 N），不能据此反推某关节最大力矩。
2. SDK set_max_current / get_now_current 使用千分比；set_max_current 是电流和力矩控制的上限设置接口，不提供 N·m 换算常数。旧 DH116(S) 单位换算文档中的 0.4/0.6 A 未明确标为 V2，不能直接套用。
3. SDK get_finger_normal_force 单位 N、分辨率 0.01 N；get_finger_pressure 的单位依赖数据格式：力帧为 N，通道归一化帧无量纲。传感器编码量程不是机械最大输出力。
4. SDK 明确包含 LAC_DOF_6_V2 手型。已查阅的完整发布包/手册中未找到 V2 逐关节电流—输出力矩曲线、减速效率和实测加载标定曲线。
5. 厂家 V2 README 明确 URDF 使用线性 mimic，MJCF 使用二次联动。两者不是同一精度的运动学模型。四指二次项在 70° 主动角处贡献约 17.15° 从动角，不能忽略其对接触点的影响。不能在当前初态不重新验证的情况下直接切换联动模型。

官方模型与本地比较
厂家提交：14275cfe32cce1fe13a16df712e8a0e610a0227e（2026-08-31）。
左右 URDF、左右 MJCF 共4个文件，去除注释和排版后 XML 数据全部相同；下载新模型不会改变当前质量、限位或联动系数。
URDF effort/velocity 字段为 0；MJCF 位置驱动 kp=50、kv=2。这些描述没有构成实机最大输出力标定，不能把 kp 直接当作厂家实机伺服刚度。
手册主动范围为拇指侧摆80°、拇指屈伸90°、四指70°；模型分别约91°、59°、90°。现有保守交集并不等于已核实真实全行程；扩大拇指角度还会与从动限位冲突。
模型质量总和左0.313947894 kg、右0.324906125 kg。finger32_link 分别0.156971898/0.162452788 kg，质心 z 分别−0.06813145/−0.06490106 m；该连杆碰撞/视觉 STL 的 z 范围约−0.00857到0.05272 m。质量分配与几何明显不相称，需厂家修正版或独立质量分布建模，不能仅补齐基座到490 g就称完成标定。

本地物理对照结果（不是 PPO 学习成绩）
v48：相同0.55 N/手目标、相同0.2 N·m驱动上限，mimic频率400/800/1600/刚性0，4环境。
前三组 close 超时；刚性组进入 lift，但手掌上升约7.29 mm，物体没有离桌，随后失去夹持。
v49：仅增加 solve_articulation_contact_last=True，重复相同4组。
前三组 close 超时；刚性组手掌上升约3.60 mm，物体最大底面变化约0.001 mm，仍未离桌。
两次进程正常退出，无记录的硬物理故障，实际抓取成功率均0。接触求解顺序调整没有在这组对照中解决问题。
从刚性组轨迹看，提升时指垫逐渐越过物体中心高度、闭合补偿达到0.08 rad限幅。说明有夹持几何/补偿行程问题，不能将全部失败归结为电机力矩小。关节跟踪最大误差低于0.005 rad，本组不是0.03 rad跟踪门限阻止提升。

对后续修改的约束
先对加载条件、接触位置/法向、联动形式与闭合方向做受控验证，再逐级验证更大目标力和驱动能力。每手两指接触力模长之和与手册单指指尖力并非同一测量量，不计算简单的“能力差14倍”。
能够由官方证据确定的参数与暂时估计项必须分别标注。当前没有完整实机标定依据；不能宣称全参数正确，也不能把失败的受控试验当作允许重启512环境学习的验证结果。
