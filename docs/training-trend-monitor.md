# PPO 学习趋势观察规则

用户确认：每 50 轮比较受力方向、夹持和实际离桌表现；连续三个比较窗口没有改善才请求专项诊断。第一组 50 轮是基线，因此从零训练最早在第 200 轮触发。进程停止、数值异常、物理越界仍走原有即时告警。

`scripts/watch_dh116_tensor_ppo.py` 使用当前 run 的连续 `iterations.jsonl`。完整窗口与此前最佳完整窗口比较，以下任一指标改善就清零停滞计数：

- 对物体的有符号竖直合力平均值增加至少 0.02 N。
- 满足夹持载荷的环境比例增加至少 0.005（0.5 个百分点）。这是夹持代理指标，并非连续稳定保持时长。
- 窗口内所记录的最大物体底面净空增加至少 0.5 mm，以排除接触抖动；桌面高度为当前场景的 0.30 m。日志只提供每轮采样值，不能覆盖所有瞬时峰值。
- 累计成功抓取数增加。

奖励增加本身不算进展，尤其不将势函数奖励的正均值当作受力改善。缺失、非有限或不连续数据不能用于判定停滞。未完成的尾部窗口不参与比较；JSONL 正在写入的残行留待下次读取。

观察器生成 `trend_watch.json`，并在 `live_watch.json` 中附带趋势状态。触发停滞时写入 `diagnostic_request.json`，该文件记录最近一次诊断请求，当前状态以 `trend_watch.json` 为准。观察器继续运行，不修改参数、不重启 PPO，也不会自行执行根因诊断或修复。

验证：`DH116_NUM_THREADS=6 bash scripts/python.sh -m pytest tests/test_dh116_training_trend.py tests/test_dh116_training_observer.py -q`。
