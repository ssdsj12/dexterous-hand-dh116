# 第五阶段物理映射与双手协同执行计划

基准为 `3f7fd69073ab9060f1932dba74d6dcb13104c6a6`。执行用户给定的 T1～T7 顺序。默认 M0，实验适配器显式选择并绑定源码 SHA。物理、奖励、关节保护和 30 mm / 5 s / 0.5 mm 判据沿用原合同。

1. T1 增加 `tabletop_bimanual_joint_tracking_audit.py`，接入已有 reset 前 480 Hz observer。重放历史 M2 动作，逐子步读取 env 932、799 和全部新终止环境的实际关节位置、速度、目标、被动耦合和指腹载荷。未提供的传感量使用带来源的无效标记。审计估算力矩的 SDK 字段及冲量时间基准。
2. T2 增加 `tabletop_bimanual_physical_action_adapter.py`，复用 USD/URDF 关节树，为两手各自构造 FK、解析 Jacobian、主动/被动耦合。对每个主动自由度正负扰动、掌心 XYZ、内禀旋转及联合动作进行解析/有限差分和原生读回比较。SDK 语义旧合同作恒等回归，几何坐标转换为显式新合同。
3. T3 沿用第四阶段的 200 初态 manifest、Checkpoint 和 seed，分别运行 Z0、Z1、Z2、Z3。Z0/Z1 保留原始及冻结动作反事实证据。Z2/Z3 读取实际净空、物体位置、双侧对向接触、固定锚滑移、关节跟踪，投影受原速度限制约束。记录全部首终止及其前的物理样本。
4. T4 协调目标报告 lift/contact/slip/joint/sync 各项，接触或跟踪失效时撤销共同向上运动。使用实际抓取点和重心计算支撑分配。
5. T5 冻结二指 Teacher + MPC 历史成功动作路径，旧路径与显式适配路径各自 4 个原生回合，核验真实净 lift、hold、滑移、双侧承托和退出原因。旧路径失败时报告复现问题，保留完整失败目录。
6. T6 三指以独立 Teacher 实验验证实际抓取与稳定 Lift，失败证据单列。只有T5实际4/4证明及其输入SHA通过后，才运行独立三指协调候选：只投影三指环境的双腕，二指动作和目标逐值保留；接触/跟踪失效暂停共同上升。逐480Hz分别保存Teacher请求和协调执行。候选三指的60Hz源请求不是其实际480Hz执行标签，即使物理成功也不得直接加入BC成功池。
7. T7 的开始条件为适配器原生验证通过、二指 Teacher 回归通过。三指训练还须三指 Teacher 独立成功。满足条件后才采集同步 RGB-D/实际动作并做 BC、DAgger 和 PPO。

所有原生作业共享单实例文件锁，启动前检查现有进程。每个实验保留独立目录、冻结源码、输入 SHA、物理状态身份、完整终止记录。CPU fixture、原生验证、Teacher 和 Student 结果分别报告。README、CHANGELOG 和阶段报告随提交更新，PR 维持 Draft。
