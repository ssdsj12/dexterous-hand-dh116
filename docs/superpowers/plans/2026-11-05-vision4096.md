# Vision 4096 on GPU 3 implementation plan

> For agentic workers: use subagent-driven-development; root alone owns native Isaac execution.

Goal: validate 4096 simultaneous mixed-grasp physical environments with a true RGB-D-only actor on GPU 3, then publish branch 11-5. Never claim untested capacity or teacher reliability.

Architecture: keep the 371D privileged critic and 3844D four-frame sensory actor. Preserve 32 rollout steps and 5 epochs x 8 logical PPO minibatches. Use a pool of at most 256 real cameras (default64), rendering frozen physical states in environment batches; move calibrated cameras and explicitly map slots. Offload float32 rollout storage to host RAM and accumulate bounded GPU microbatches within each logical optimizer update. Reduce exact CAD-height temporaries by environment chunking. No physics parameter/contact/geometry simplification.

Files and responsibilities:
- Camera agent: src/go2_pvcnn/control/dh116/tabletop_vision_batched_camera.py, old camera adapter and tests. Default all-visible mode skips visibility changes; optional batch mode calls prepare_bounded_visibility(world,batch_size) after cloning and before first sim.reset, keeping source0 visibility constant. BoundedVisionCamera.sample returns the existing packet layout for all environments. Same-render-product timestamps, actual extrinsic readback, one discarded render after moving, no GT fallback. Disable native temporal anti-aliasing/frame generation and process RGB-D in exact 64-environment chunks to bound temporaries.
- PPO agent: tabletop_vision_ppo.py and make_vision_algorithm factory. CPU float32/pinned storage; inference and optimizer microbatch caps default128 (production may explicitly select larger validated caps). Loss is weighted by micro_count/logical_count; one clip+Adam step per logical batch. Verify full-batch and accumulated parameter/gradient agreement with synthetic data.
- Memory agent: tabletop_native_height_batch.py and tests. Compute exact float64 heights with bounded environment chunks, retaining all CAD vertices and global amin. Verify 4096-shaped allocation bound and equality with original on small cases.
- Root: CLI flags, training contract version/caps, camera bootstrap, startup telemetry, integration tests, native capacity and Git publication.

Validation:
1. CPU tests for numerical equivalence, actor/critic isolation, camera grouping/order/visibility/time, missing data and resume contracts.
2. Pause monitor and stop existing 64-env training only after verifying its atomic checkpoint. Never start a second Isaac.
3. Run 128, then 512, then 4096 environments with production 320x240 RGB-D and real PPO. Require two complete 32-step PPO updates at 4096, finite policy/losses, all camera initial geometry P95 within3mm, real readback for every group, and no PhysX contact/buffer overflow. Record peak memory, camera validity and throughput. Abort safely on OOM/invalid data; preserve checkpoint.
4. If 4096 fits, use a fresh4096 actor chain and absolute2048-update target; update the existing monitor to this exact run and reset policy-specific peaks. If it does not fit, report the measured limit and do not publish a claim of4096 validation.
5. Import exact validated source into the clean 11-5 worktree, repair the pre-existing reference-profile assertion without changing rewards, update README/CHANGELOG with implementation/offline/native/success distinctions, run publication regressions, review, commit and push without force. Verify remote SHA.

User approved the4096 goal and publication; routine implementation choices continue within that scope. No extra GPU or physics changes are authorized by this plan.
