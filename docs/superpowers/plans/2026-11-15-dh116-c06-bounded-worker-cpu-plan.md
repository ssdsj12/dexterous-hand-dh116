## Design choices and limits

Recommended approach: minimal versioned dispatch plus pure CPU contracts. Reusing v1 by raising its 240 cap would expand old authorization; copying the scheduler would duplicate receipt/retry/resource logic. Both are rejected. No approved authorization file, resource reservation or candidate recipe is written in this CPU package. Test JSON is explicitly synthetic CPU fixture evidence and cannot qualify native execution.

The only supported new execution profile is Pinch `approach_wiring_smoke_v1`, one environment, one episode, one Reset, 32 controls, 8 SDK/control, 256 measured SDK, 12 internal solver substeps/solver call, at most one additional accepted PPO update. Setup budget is an explicit finite new declaration and must be measured; the first candidate is two setup steps, making 258 total, but no existing native budget is spent. No later Reset beyond current source `_clock <= 240` is offered. Full/Tripod/Power and recurrent reset protocols are rejected.

## NativeProvider construction boundary (design before implementation)

No native provider placeholder is delivered. Subsequent provider implementation must use exact real scene APIs: `prepare_scene(project, capture_dir=..., sdf_dir=...)`, `assemble_prepared_scene(sim,project,prepared)`, `load_sdf_arrays(prepared)`, `validate_simulation_settings(sim,prepared)`, `bind_actual_geometry(..., read_clock=...)`, and `v2.external_wire_layout()`. Use real `FreeRodRuntime` -> one `RopeBatch` -> `DualHandRodRuntime`. Borrow construction from `build_reset_owned` before its first episode Reset; it already performs `sim.reset` and cannot supply a `new` episode as-is.

Provider owns App/SimulationContext/stage/hands/rod/RopeBatch/native handles and callbacks; C04 `NativeEpisodeOwner` borrows them, uses `MeasuredMeshReset`, numeric and mounted guards, and only restores callbacks on close. Initial setup emits actual SDK boundaries. One original `DualHandPhysicalEpisode` with physics end258, not a modified legacy recipe. `profile_reader_scope(real BackendProfile)` covers all readers. The new Pinch owned-policy reader from qualified C04 is required; frozen action readers cannot serve sampled PPO actions.

`acquire` uses C04 create collector and C05 `run_updates`; save the returned current collector with clean checkpoint before close. Drop collector, factories, closures and native aliases inside `run_owned_call`, exporting only pure-owned numerical/report data. Outer `run_lifecycle` owns synchronize -> clear/drop SimulationContext via `clear_known_simulation_instance` -> STOP -> gated AppUpdate -> App.close. Lifecycle's historical `ppo_updates=0` is not read as training evidence. Real training counters/checkpoint SHA are independently checked. Exceptions preserve failure and cleanup evidence, no os_exit/signals/fake exit success.
