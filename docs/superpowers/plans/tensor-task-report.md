# Tensor task implementation report

Implemented `src/go2_pvcnn/control/dh116/tabletop_tensor_task.py` and `tests/test_dh116_tensor_task.py`. No existing files edited, no commits, no Isaac launch.

API: `TensorTask(template_env, num_envs, device)` clones initialized full-hand force-feedback state onto device, with no retained environment objects. `begin_step(actions)` validates and returns safe float64 actions; invalid rows terminate with invalid_action. Parent calls `control(actions,live,dt)` and `consume(measurement,live,dt)` for each physical substep, then `end_step()` returns `(observation,reward,done,extras)`. Extras include phase/success/failure snapshots, term snapshots and used_time. `reset(ids,measurement)` restores seeded task/controller/reference/history only for selected IDs and accepts either full-batch or selected-row measurements. Physical reset remains parent-owned. Exports `FAILURE_NAMES` and `FAILURE_CODES`, zero denotes no failure, and nonfinite_joint_state is available for the world safety adapter. All requested state attributes exposed. end_step updates previous command before observing, matching TabletopEnv.finish_transition. Reset excludes immutable link-group metadata even if environment count equals link count.

Observation matches scalar 148D full-hand contract, float32; task/controller math float64. Controller preserves filtering, force request/rate/boost, palm compensation/envelope, active target limits, mimic correction, rate limiting and lift gates. Contact contract validates finite nonnegative additive link/group/hand loads. Finite normalized observations and measured motion checked before accepting physical measurements; bad rows retain prior finite observations.

Reward version `phase_potential_v1_10n_5`: measured total contact load delta yields up to 5 at 10N, positive shaping only during prior close phase. Negative contact-potential changes during prior hold are charged as well, so hold loss followed by close reacquisition cannot repeatedly earn unpaid contact gains. Readiness progress potential is continuous close 0..1, hold 1..3, lift retains3; regressions repay prior readiness gains. Lift uses measured bottom height delta, stable dwell potential up to2 with negative regression, and existing costs and terminal ±25. Hold additionally penalizes slip beyond .003m on the tabletop; lift retains .02m tolerance. Dwell thresholds close .2s, hold .3s, lift success .5s at actual bottom >=.33m. No stage-entry bonuses.

Validation: `DH116_NUM_THREADS=6 bash scripts/python.sh -m pytest tests/test_dh116_tensor_task.py -q` — 8 passed, including CUDA residency (CUDA available), CPU force controller differential against BatchTask on 20 randomized synthetic ticks and scalar observation parity. Tests additionally cover exact dwell boundaries including 480Hz 96/144-substep close/hold transitions, repeated readiness cycles with zero net windfall, phase regression and repayment, unsupported phase transitions, real measured lift, lift dwell loss, contact normalization/phase restriction, finite fallback, invalid action termination, selected reset, and single terminal penalty, and three repeated 0.2s close→hold→loss→reclose cycles at differing measured loads with unchanged net contact reward. Hold support increases are explicitly tested to give zero positive contact shaping.

Limitations: physical GPU integration and Isaac validation are parent-owned; these tests use synthetic measurements. Rigid object only by design. The task accepts measurement integer joint_failure from parent's physical safety adapter. No empirical grasp success claim.

Follow-up review closed the contact-cycle exploit by charging negative measured contact-potential deltas in hold. Nonfinite task and observation measurements continue to set `nonfinite_state`; fatal process handling of this code is parent integration responsibility.
