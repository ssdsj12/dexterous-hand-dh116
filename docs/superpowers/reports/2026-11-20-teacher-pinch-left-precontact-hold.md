# Pinch 左侧接触前撤回旧目标

对齐两轮原生 SDK58–60 后，两轮线缆节点逐点一致。原路线从 SDK52 已出现左拇指单侧载荷。SDK42 左拇指在实测姿态的杆间隙为 0.198 mm。到 SDK50，实测仅有 0.031 mm，旧目标的预测间隙已经为 −0.0023 mm。此时才暂停左手无法保证整个旧目标包络维持无接触。

`prepare_dh116_pinch_precontact_hold.py` 读取经过 SHA 校验的历史账本，以实际 41 节点、左右关节读回和 solver pair 验证未出现手杆接触。它计算左手撤回轨迹，主动消除多余腕位姿命令，拇指和食指保留 12% 的旧指目标增量，其他指目标撤回实测位。24D 动作保持原排列和速率，右手通道均为零。这里的零只表示诊断候选没有额外右手动作，原生组合仍需分别安排并验证右侧控制。

| 左侧接触前边界 | 证明的凸包 | 最小条件净空裕量 | 结果 |
| --- | ---: | ---: | --- |
| SDK18 | 22 | 71.0 µm | 通过 |
| SDK26 | 22 | 17.1 µm | 通过 |
| SDK34 | 未完成 | — | 左拇指远端仍有未决盒 |
| SDK42 / SDK50 | 未完成 | — | 左拇指远端的独立旧目标盒不能证明无杆接触 |

证明包括左手目标指腹、桌面、全左手已读回凸包、旧指腕目标分量与 50 µm 杆节点条件余量。两个通过边界均只需要一个非零原速率控制窗。非零动作在下一次原生运行前须由当次 SDK 读回重新计算并核验，当前 CPU 结果不证明左右手已经完成抓取。

右腕只回调阶段在旧账本 SDK50 的杆快照上通过 22 个凸包的条件检查，最小裕量 0.390 µm。SDK42 的右近端盒未通过。优先把左侧 SDK18 收住、右侧 SDK50 调角组合成独立试验，运行中持续读取所有手杆接触、腕目标与漂移；右侧平移和合指各自另做现场放行。若在新实例不能保住左侧净空和杆静止条件，则保留首个终止样本。

207 项相关 CPU 回归通过。这一组包括命令合同、两侧目标几何和当前账本回归。先前额外运行的历史集合为 430 通过、33 失败、2 错误，涉及冻结历史回执/源码身份以及 worker 进程夹具。另一个扩展集合为 88 通过、3 失败。两组未恢复到全绿，未替换历史回执。此工作包没有启动 Isaac 或 PPO。

复算命令为 `python -B -m scripts.prepare_dh116_pinch_precontact_hold --archive <verified-native-dir> --sdk 18 --output <new-receipt>`，另一档使用 `--sdk 26`。
