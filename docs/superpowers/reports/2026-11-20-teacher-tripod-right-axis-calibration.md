# Tripod 右手逐轴原生跟踪标定

历史 SDK178 数据只包含正向 `finger12`、`finger21`、`finger31` 和腕部局部 Y/Z 的主要运动，无法验证候选的反向拇指、腕 X 或旋转。新配方将同一候选的右手起点和目标整体提高 16 mm，在自由杆留在原桌面的情况下，执行原幅度、原速率约束内的右手动作。左手停放。只记录无接触状态下同钟 issued target 与实际关节回读。

| 右手轴 | 最大绝对跟踪误差 | 停稳 8 步后的误差绝对值 |
| --- | ---: | ---: |
| finger11 | 0.739 mrad | 0.342 mrad |
| finger12（反向） | 0.310 mrad | 0.123 mrad |
| 腕局部 X / Y / Z | 5.62 / 86.25 / 33.12 µm | 1.30 / 17.01 / 6.68 µm |
| 腕 roll / pitch / yaw | 0.648 / 9.227 / 0.861 mrad | 0.596 / 7.813 / 0.730 mrad |

右腕 pitch 在无接触条件下仍有约 46 SDK 步的最大表观滞后。该数值来自本配方的目标变化率和跟踪残差，只用于定位需要分相位的轴。后续优先提早旋转，并在实际腕位收敛后才允许向杆闭合。接触状态的动态界限、近端净空和抓取仍需验证。

第一次新配方的数据包版本被旧记录器拒绝，零 SDK 物理步，正常返回 App 关闭但外层退出 1，作为失败保存。修正接口后，CPU 预检使用同一旧记录器检查。第二次单实例原生完整记录 22 个控制窗、178 SDK 步（含 2 个初始化）、2,112 求解器子步，无手与杆接触，外层自然退出 0。124 项相关 CPU 回归通过。两轮均零 PPO。

入口 `python -m scripts.run_dh116_tripod_right_axis_calibration`。使用独立计划和输出目录。结果 SHA 和首次失败回执见 readiness。
