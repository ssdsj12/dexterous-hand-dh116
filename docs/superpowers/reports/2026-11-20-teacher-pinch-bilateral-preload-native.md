# Pinch 四指固定腕预载原生诊断

本轮经 Antigravity 复核后，使用 SDK202 当步的实测状态重新锚定左右手位置和关节跟踪域。两次策略窗只推进左右拇指与食指，随后用八次零增量策略窗观察；两腕目标保持固定。追加动作必须先通过现场姿态重放、同一求解器步的双侧反作用力方向核验和独立净空证明。旧 0.05 N 单指、0.3 N 每手及方向门槛仍用于统计合格接触。

| 结果 | 左 | 右 |
| --- | ---: | ---: |
| 接触方向合格的子步 | 960 / 960 | 960 / 960 |
| 接触载荷合格的子步 | 70 / 960 | 0 / 960 |
| 每手拇指与食指合力峰值 | 0.322154 N | 0.294136 N |
| 最后一个子步的合力 | 0.281533 N | 0.266570 N |

相较原边界的 0.168709 N 和 0.144407 N，预载提高了实测反作用力。四指同时超过 0.05 N 有 943 个子步；两手同时满足完整载荷门槛为 0 个子步。追加阶段仍记录了 36,714 个桌面接触条目。没有下发离架抬升动作，稳定抓取和 Teacher 准入仍待验证。

原生在 GPU 2 上单实例完成 1 环境、35 个控制窗、282 SDK 步（2 初始化、280 测量）、3,360 个求解器子步。零 Teacher 查询、零 PPO；外层自然退出 0（240.15 s）。原始账本和回执 SHA 见随附 readiness 文件。左右几何证书最小余量分别为 0.114 µm 和 146.439 µm，两手后续应独立选预载，重新从本次实测关节和杆节点验证。该余量是证书下界，以当前固定输入为条件。

Ubuntu 运行入口为 `python -m scripts.run_dh116_pinch_bilateral_preload`，先通过 `--plan` 与当前归档输入生成独立冻结文件，再用完全相同输入和 `--approved-frozen-sha256` 启动。无自动重试和强制关闭。CPU 回归命令为 `python -m pytest -q` 加入 Registry 中该工作包的测试路径（222 项通过）。
