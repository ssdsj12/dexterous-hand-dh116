# Teacher friction readout: independent training-source binding

The primary objective remains actual grasp and off-support Lift/Hold, rather than additional general safety work.
The current camera-free actual factory only admits short approach/contact diagnostics; its reward has no Lift/Hold terms.
This package connects the independently built friction readout to the parameter/health/build/Reset-radius reader scope needed by the full training successor. It does not complete that successor.

## Actual changes
- `tabletop_contact_friction_observation_source.source_basis()` reads the complete original source provenance plus all72 derived files, exactly3 deltas, new binary, Python facades, source preparer, build receipt, and existing finite standalone GPU parity evidence.
- `source_scope()` binds the actual parameter/health/build/radius readers explicitly. Legacy source/profile scopes cannot cross this scope. One thread may nest; another thread is rejected. Original values are restored after caller exceptions.
- `FrictionBackendProfileV2.load()/verify()` composes the original immutable BackendProfile (including per-side USD and10 pad SDF identities) with the new source inventory and reader bytes. It has its own digest and exact type.
- `friction_profile_reader_scope()` refuses self-consistently rehashed caller profiles when nested under another owner. Original BackendProfile gates, V1/V2 CPU model namespace, original defaults and historical checkpoints are unchanged.
