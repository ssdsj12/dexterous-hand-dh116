# Tripod 从原生靠近末端继续到指定路点

沿用已独立验证的 SDK 240 初态和 272 靠近末端。先精确重验前四个动作窗的双方 q、qd、下发目标、实际根安装和 41 节点状态，再从同一原生动作会话继续到左侧路点 1、右侧路点 2。使用原 24D 动作合同，按真实后端关节目标和世界坐标计算平移、按原安装姿态与内禀 XYZ 计算旋转，各手有单独的目标。

复查 SDK 264–272 的实际杆形，对两条拟议末段的离线路径估计留出左手至少 0.929 mm、右手至少 0.542 mm 保守间隙。原生每步继续读取最新杆快照和实际包络，审计桌面、支架及接触，0.25 mm 保守杆间隙守卫生效。新增原生动作与物理边界同钟的真实关节连杆位姿、质心和桌面净空。路线所需的原始动作组幅值、两侧独立原生读回、输入物理时钟身份均受控。

冻结命令 `python -B -m scripts.verify_dh116_tripod_supported_reset --approach-reference BASE --waypoint-reference APPROACH --waypoint-geometry SCREEN …`。独立预算为 432 SDK 步、24 控制窗、5160 求解器子步、零 PPO、240 秒软上限。112 项 CPU 回归通过。当前结论仅覆盖现场试验的准备和来源，许可范围为未接触靠近。
