# Actual Teacher diagnostic checkpoint origin

The first bounded Pinch diagnostic made one real PPO update and sealed a checkpoint. Its original checkpoint bytes still match the published digest. At audit baseline fcd054f, the source inventory already rejected that historical recipe because two entries from its original file list had changed. The next A and B runs require one shared, newly frozen source and training contract.

Antigravity reviewed the launch, provider, parent scheduler and both artifact auditors. The follow-up confirmed that the old qualified-checkpoint resolver expects a different receipt and cannot establish a source for actual diagnostic resume.

The scheduler now exposes a dedicated origin reader for published, actual A diagnostics. It reuses the original parent approval, intent, lock, budget, GDB natural-exit and raw-artifact audits. It requires matching source and training semantics, verified Reset and model-input source, update/version 1, original owner scope, complete checkpoint metadata and a second digest check of the canonical checkpoint path. It retains the producer episode identity and both weight and checkpoint digests. The origin carries no new native, grasp or Teacher qualification. The existing diagnostic command keeps its original output shape.

The CPU regression passed 205 tests. Negative cases cover changed source/config/Reset, a different rollout, changed checkpoint bytes, CPU fixtures, missing Reset or episode identity, and unpublished receipt summaries. This package used no Isaac, GPU or optimizer budget. The worker role stays disabled while the independent B update, parent/child authorization path and role-aware artifact audit are wired.
