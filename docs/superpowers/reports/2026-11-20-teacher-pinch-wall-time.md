# Pinch PPO 分段墙钟诊断

v11 的 8 个稳定控制窗平均耗时 6.807 秒。开始采集时只剩 78.241 秒。对同一真实来源清单做了 8 次 CPU 测量，192 个文件共 50,761,565 字节。控制窗进入来源绑定的中位数 0.280 秒，退出前复查中位数 0.211 秒。单次权重摘要约 0.252 秒，物理证据的典型单条序列化与 fsync 约 0.032 秒。这些微基准不能代表完整原生窗口。

和 Antigravity 在同一工作树 `3d057f0` 上复核后，采用每个控制窗一条独立 `control_window_wall` 记录，写入已有生命周期 trace。记录来源绑定、动作前处理、物理控制与动作后处理的单调时间，另外报告物理观察器在物理控制内的子计时。观察器覆盖实际交付、证据写入和同步验证。SDK、杆求解器和两者之间的读回暂共用物理控制桶；差值是观察器之外的耗时，不能解释为单独的 GPU 执行时间。没有包装生命周期对象、手部变换读回或杆求解器回调。原训练账本格式、碰撞保护、奖励、24D 动作与 checkpoint 验收保持原合同。

完整、终止与异常控制窗都保留各自结果。记录 `sdk_steps_delivered` 仅计已经进入观察器交付的子步。原始来源故障优先于次生的 trace 写入故障。正常控制窗的 trace 写入失败会阻止这次诊断继续，已经提交的 transition 保留，且日志故障本身不会将该 transition 标为来源隔离。

对 v9/v10/v11 共 139 个真实物理子步做了左右分别归一化的离线复放。右手保留 v11 Reset，基于实测和 SDK 目标包络的最低值为 2.171756 mm。初批左手提升候选中，达到端点原 0.05 mm 几何判据的一组，在连续闭合中拇指近节对杆包络的保守间隙为 −0.011141 mm。第二批加入独立腕姿调整，得到连续几何通过的若干组，但它们尚未达到各自按原候选合同声明的额外储备。此轮没有把替代 Reset 晋级。复放不包含新姿态下的双向力反馈、策略闭环、接触和持有。

配方 `teacher.pinch-ppo-fresh-smoke32-wall-profile` 复用 v11 封存 Reset，冻结指纹 `90c665c67952e9682b6d71fb16302325d968acfaa215fbdb072126d69cf3395c`。预算为 GPU 3 单实例、1 环境、2 个初始化 SDK 步、最多 256 个测量 SDK 步、3072 个求解器子步和 1 次更新，180 秒内层、240 秒外层。任何已知物理保护触发仍需传递原始失败。原生计时结果由独立回执单列。

第三批再加入世界 X 轴的小角度调整，3 组候选同时通过原 0.05 mm 端点、完整连续路径和抬高储备。第二组相对 v11 左掌 +125 µm Z、+30 µm X，绕 world X −1.2 mrad、world Y −0.4 mrad、finger12 +1.75 mrad。实测和目标复放最低 2.313649 mm，连续净空下界 2.327456 mm，拇指近节对杆包络下界 0.044937 mm。下一次 Pinch 先封存该候选自己的真实 Reset，再绑定同一计时方式。匹配 v11 原 Reset 的配方保留用于需要单变量定位时。

188 项 CPU 回归通过，含源完整性、生命周期、故障优先级、原训练与 GDB 握手。此工作包新增原生次数和 PPO 更新均为 0。
