# Power 双手共用任务杆

Power 入口在原始实测 Reset 之后，把左右掌面各自已核验的 SDF 注册在同一根原任务自由杆的槽位 11 和 12。原有十个指腹和桌面槽位保持顺序。每次更新用当步实测的 PhysX 连杆位姿和质心，每侧分别提交五指和掌面的反作用力。写入力来自上一完整物理交换。原十一槽运行时及历史源码 SHA 保持原样。

| 原生验证 | 结果 |
| --- | ---: |
| Isaac 实例 / 自由杆 / 槽位 | 1 / 1 / 13 |
| 一次性接触缓冲容量 | 6,396 |
| SDK 初始化 + 测量 | 2 + 8 步 |
| DeformX 求解器 | 96 子步 |
| 原子接触对 | 桌面 3,936，手指和掌面 0 |
| 聚合力守恒最大残差 | 1.456e-6 N |
| 最小桌面净空 | 左 2.11084 mm，右 2.11635 mm |
| 进程自然退出 | 0，32.86 s |

原生诊断保持原驱动目标，零 PPO。该实验验证共享杆上的真实槽位、时钟和交换。上一工作包验证过独立掌部加载，本轮没有共享杆掌面接触，带载五指包覆和净抬升仍待验证。

两次早期尝试都在 SDK 2 停止，第一轮因 RopeBatch 拒绝二次分配，外层 SIGSEGV（-11）。第二轮提前预留容量后触发旧十一槽专用数值 Reset 校验，外层退出 1。修正版复用原始实测 Reset 的通用入口，并在底层唯一一次分配中预留 13 槽容量。原始失败回执均已封存。

Ubuntu 入口为 python -B -m scripts.verify_dh116_power_shared_rod，传入 --rays、--left-bake、--right-bake、--output 和 --plan，启动时追加对应 --approved-frozen-sha256。联合 CPU 回归 202 项通过。最终针对旧 Reset 与共享容量的回归 59 项通过。附加历史参数读取套件有 6 项失败，其固定的 FreeRodRuntime SHA 4e0f7762 与父提交中已存在的 7a38bb78 不符，该读取器及历史运行时未改动。
