# DeformX zero-time Reset pose commit

The existing ropesim bridge queued Reset teleports for consumption at the next solver call. A controlled first exchange can replace that target before it is consumed. The stationary Power fixture now avoids that race, but it requires an immobile first SDK exchange. An optional GPL-3.0-only patch now exposes `RopeBatch.commit_mesh_reset_pose(index, pos, quat)` for a host-supplied XYZW pose. It synchronizes a single committed mesh and invalidates stale contact readback while preserving other queued mesh targets. Solver time and rod state remain unchanged.

The patch was applied in independent copies of both the existing pair-capture source and the locked Teacher observation source. The Teacher candidate differs in exactly three out of 72 source files. Its cp310 extension was compiled using the existing isolated CUDA 12.8.61, with seven SM89 cubins verified by cuobjdump. The base Teacher binary retains SHA-256 `8817010163946945495c987923d11f3ade4fbd52482a83bbdd48f017d3149340`. The independent candidate SHA-256 is `1b2c5a1a685c9e6e0e3171f926ce4f8eddfce3f589dd739166aedf75948c6199`. The checked patch SHA-256 is `3f1b55f1b2a315ba694ec2c1789078b10a218c493225fd746cdca2531b171c1a`.

The installed GPU solver test first detected the missing API on the baseline. With the candidate, an immediate Reset followed by a commanded sweep matched direct initialization exactly in rod positions, velocities, force/torque and the 10 pair samples. Those contacts first appeared at substep 8. The legacy queued Reset produced only four pairs. A second mesh's previously queued motion was preserved, and committing a Reset after a known contact packet made the packet unavailable. Reproduce in the isolated CUDA environment using `python -B -m scripts.verify_dh116_deformx_reset_pose_cuda` with the candidate package first on the diagnostic Python path. The relevant CPU regressions passed 102 tests.

This package proves the GPU interface in a standalone fixture. The current Isaac and Teacher loaders still attest the old backend. The next task is to bind a separate candidate profile at the real episode Reset and compare one first controlled SDK interval. Existing physical settings, actions and checkpoints retain their current contracts.
