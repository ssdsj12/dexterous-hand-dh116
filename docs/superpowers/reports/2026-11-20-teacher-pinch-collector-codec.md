# Pinch 原生采集器的等价编解码

Antigravity 审查确认仓库已有有限数值数组编码器。此次直接复用该函数，在采集器内部接入逐行证据、拥有副本和 SHA 计算。没有使用会替换全局 replay 函数的上下文。原编码只读回放模块继续使用历史代码和 SHA。

保持负零、原 dtype 标签、NaN/Inf 标记、JSON 字节、拒绝非拥有对象、dataclass 和只读映射序列化、终止记录与逐行 fsync。复制仍通过原解码器，因此 tensor 归一化为独立 NumPy 数组、tuple 转 list、拥有数据内存分离。Checkpoint 和独立审计继续使用原有读取和哈希路径。

对 v12 日志中 187 份实际物理、交换和观测载荷，先核对原日志 SHA，并交替执行四次旧路径与新路径。原始 JSON、SHA 和复制后的规范字节全部相同。计时是该 CPU 测量序列的中位数，不含原生 PhysX、CUDA、逐行 fsync 或全部观测计算。

| CPU 子路径 | 原路径 | 新路径 |
| --- | ---: | ---: |
| JSON 编码 | 4.3190 s | 2.3964 s |
| 所有载荷 SHA | 4.3484 s | 2.5330 s |

208 项相关 CPU 回归通过，含新添的 10 项等价/拒绝回归和原非法来源链路。该修改尚未在原生新配方上测量。Pinch v12 原试验保持消耗，未来配方须重新冻结代码闭包并包含已有快速编码器。当前结果无法证明 32 控制窗可在现有预算内完成。
