# Pinch 预抬升保持目标与过渡风险

基线 `220ff32`。Antigravity 核对原生闭合入口、动作积分和保持设想。原生 SDK74 左、右食指实际滞后为 6.266/5.393 mrad，右腕需约 1.99 个原旋转速率窗才能撤回实测姿态。复核建议先考虑保留手指旧目标以维持法向预载。我们用已验证同钟的第 74 个边界复算了手指比腕快的反例，判断是否能把这个做法作为保持入口。

## 反例

腕固定在 SDK74 实测位姿、拇指和食指追到旧目标时，右拇指近端 `source:finger13_link` 对线缆的间隙**上界**为 −0.2291 mm。左侧 `finger13_link`、`finger22_link` 的上界也小于零。上界来自可行的凸包和杆最近点见证。这是明确的条件几何相交，尚未在新动力学轨迹执行。仅撤腕目标并保持手指旧命令的方案缺少可用的异步安全区间。

## 实际实现

`prepare_dh116_pinch_prelift.py` 从原生回执读取当前姿态和 SDK 目标，保留左右拇指和食指原正向目标差的 12%/10%。左腕收至实测位姿，右腕转角保留旧误差的 25%。原 24D 动作编译为两窗限速回调加两窗观测。平移、转角及每个指通道沿用原速率边界。该动作表的首要用途是说明可到达的目标，初始旧驱动的跟踪瞬态仍需单独验证。

以固定的实测杆形为参考，给每节点留 50 µm 敏感性，独立覆盖拇指、食指、腕平移和腕旋转的 0–100% 目标响应。左侧一块、右侧十一块完成独立重查，右侧最小几何裕量约 0.12 µm，且目标名义 SDF 四个指腹均为负。这是很紧的条件目标区间。真实弹性响应、接触受力、支撑释放和保持窗口必须另行验证。

运行 `python -B -m scripts.prepare_dh116_pinch_prelift --archive <sealed_wrist_relief_native> --output <new_json>`。相关 CPU 回归 188 项通过，零新增 Isaac 物理步、保持、抬升和 PPO。下一步从更早的闭合控制窗消减指目标超前，或重新选取右近端净空更大的接触目标，再验证闭合到保持的实际物理过渡。原训练晋级标准保持不变。
